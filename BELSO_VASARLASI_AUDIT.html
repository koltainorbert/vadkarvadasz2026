1. Vezetoi Osszefoglalo

Statusz: A rendszer mukodokepes, a hibrid upgrade modell aktiv, a maradek ertek kompenzacio mukodik, admin felugyelet bovitve.

Audit konkluzio: 1 kritikus hibat talaltunk es azonnal javitottuk. Nyitott blokkolo hiba jelenleg nincs.

Fontos: A kompenzacio pontossaga uzletileg jelenleg az aktualis kartyaarakra tamaszkodik (nem a historikus vasarlasi arakra). Ez uzleti dontes szerint finomithato kesobb.

3. End-to-End Mukodes (Pontrol pontra)

3.1 Vasarlas inditas (frontend)

  1. User a /va-kredit-vasarlas/ oldalon csomagot valaszt.
  2. Rendszer ellenorzi: be van-e jelentkezve.
  3. Ellenorzi: a valasztott mennyiseg valos, aktiv kartya-e.
  4. Fut a szabaly: aktiv csomag mellett csak magasabb rang vasarolhato.
  5. General token, tranziensekbe menti: user, qty, amount, provider, return_to, created_at.
  6. Stripe provider eseten Checkout Session letrehozas, redirect Stripe-ra.

3.2 Fizetes visszaerkezes (callback)

  1. Success URL visszahivja a callback-et tokennel (+ Stripe session_id).
  2. Rendszer validalja sessiont Stripe API-val (status=complete, payment_status=paid, token egyezes).
  3. Meghivja a veglegesitest: finalize_credit_purchase().
  4. Siker eseten flash uzenet: vasarlas rendben + kompenzacio info (+X nap, Y Ft).

3.3 Stripe webhook (aszinkron biztonsagi ut)

  1. Webhook alairas ellenorzes (Stripe-Signature, tolerance ablak).
  2. Idempotencia event szinten transienttel.
  3. checkout.session.completed eseten fallback adatokkal finalizalas.

3.4 Veglegesites (kredit + csomag + kompenzacio)

  1. Kredit jovairas: va_listing_credits += qty.
  2. Cel plan kiszamitas qty alapjan.
  3. Ha upgrade (uj rang magasabb):
    • Maradek ido kiszamitas regi lejartbol.
    • Maradek ertek (Ft) becsles regi plan napi ertekebol.
    • Uj plan napi ertekevel atszamolt kompenzacios nap.
    • Guardrail: min +1 nap ha van maradek ertek, max +365 nap.
    • Uj lejarat = uj plan alap nap + kompenzacios nap.
    • Lejarati warning flag-ek reset.
    • Upgrade email kuldes.
  4. Kiemeles cooldown szinkron a valasztott kartyarol.
  5. Vasarlasi history mentes + paid transient idempotenciahoz.
  6. Plan limit enforce futtatasa.

5. Adatmodell es Tarolas

5.1 Uservmeta kulcsok (fobb)

  • va_plan - aktualis plan slug
  • va_plan_expires_at - Unix timestamp
  • va_listing_credits - vasarolt kredit egyenleg
  • va_plan_boost_cooldown - user szintu boost nap
  • va_credit_purchase_history - vasarlasi lista (upgrade + carryover mezokkel)

5.2 Tranziensek

  • va_credit_token_{token} - pending vasarlas payload
  • va_credit_paid_{token} - mar feldolgozott tranzakcio idempotencia
  • va_stripe_evt_{event_id} - webhook event idempotencia

5.3 History bejegyzes mezei

  • Alap: token, qty, amount, provider, return_to, plan_slug, stripe IDs, initiated_at, completed_at
  • Upgrade extra: upgrade_applied, carryover_days, carryover_value_ft, prev_plan_slug

9. Uzemeltetesi Checklist (Adminnak)

  1. Stripe provider aktiv + secret key megadva.
  2. Webhook endpoint aktiv + signing secret beallitva.
  3. Kreditkartyak qty/price/plan_slug konzisztens.
  4. Upgrade email sablonok kitoltve, tokenek tesztelve.
  5. Teszt userrel vegigfuttatni: basic -> silver -> gold upgrade.
  6. Ellenorizni: flash uzenet + email + admin kompenzacio sor.

10. Support Forgatokonyv (Gyakori kerdesek)

"Elveszett a maradekom?"

Nem. Upgrade eseten a maradek ertek automatikusan hozzairva napok formajaban. Ellenorizheto emailben es admin history fejlécben.

"Miert nem vehetek kisebb csomagot?"

Aktiv csomag mellett csak magasabb rang vasarolhato, hogy ne legyen felhalmozasi anomalia.

"Mi tortenik duplaklikk/dupla callback eseten?"

Idempotencia token/session/intent/event szinten vedi a rendszert duplikalt jovairastol.

11. Valtozaskezelesi Javaslatok (kovetkezo kor)

  • Historikus plan ar tarolasa aktivalaskor a pontosabb kompenzaciohoz.
  • Kompenzacio szamitas log audit trail kulon usermeta mezoben.
  • Admin oldalon kulon "Kompenzacio tortenet" details blokk.
